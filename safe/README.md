# Как защитить свой проект

Эти промпты помогают поручить Codex или Claude Code проверку приложения, настройку сервера и восстановление после аварии. Агент изучает проект, выполняет работу и проверяет результат. Вы сообщаете недостающие факты и выбираете допустимые последствия.

## 1. Выберите промпт

| Что происходит | Что открыть |
| --- | --- |
| Проект работает или ещё разрабатывается. Хотите проверить его безопасность | [Промпт 1 — защита приложения](master-prompt-1.md) |
| Нужно настроить собственный Linux-сервер (VPS), проверить существующий или переехать на новый | [Промпт 2 — настройка VPS](master-prompt-2.md) |
| Подозреваете взлом, утёк ключ, повреждены данные или сайт не удаётся восстановить обычным способом | [Аварийный промпт](incident-prompt.md) |

**Обычно начинают с первого промпта.** Второй нужен только для VPS. Если сайт размещён на платформе, которая управляет сервером за вас, первый агент подготовит подходящий путь настройки. Покупать VPS ради промпта не нужно.

Аварийный промпт запускают по необходимости. Это не обязательный третий этап; при аварии не нужно сначала проходить первые два.

## 2. Запустите в проекте

1. Откройте в Codex или Claude Code папку с актуальным кодом вашего проекта. Сохраните копию важных данных, если они уже есть.
2. Создайте новый чат с доступом к этой папке. Для каждого промпта рекомендуем отдельный чат, хотя это не техническое требование.
3. Откройте выбранный промпт по ссылке выше и **вставьте его целиком**. Его подробные технические инструкции предназначены для агента — разбирать каждую перед запуском не требуется.
4. Кратко расскажите, что делает проект, работает ли он уже для пользователей и есть ли важные данные. На неизвестный вопрос можно ответить «не знаю».
5. Агент изучит проект, объяснит план и начнёт работу в согласованных границах. Отвечайте на вопросы и выполняйте шаги, для которых нужен ваш доступ.

Для автоматических проверок в GitHub понадобятся проект в Git и аккаунт GitHub. Если это ещё не настроено, сообщите агенту — он должен дать понятную инструкцию.

**Не вставляйте в чат пароли, ключи доступа (токены), приватные SSH-ключи, содержимое `.env` и данные пользователей.** Когда потребуется секрет, агент объяснит, куда добавить его самостоятельно.

Если нужен только план, напишите это перед промптом или используйте режим планирования. Для выполнения изменений предоставьте доступ на запись в папку проекта. Специальные фразы подтверждения и обязательное переключение режимов не нужны.

### Если выбрали VPS

В новом чате должны быть доступны результаты первого промпта или уже существующие требования приложения. Отдельный файл с определённым названием не обязателен: агент сначала проверит имеющиеся сведения.

Сообщите, есть ли сервер, работает ли на нём сайт, его адрес и данные подключения, которые знаете: имя пользователя и порт. Пароль и приватный ключ не отправляйте. Если подключение ещё не настроено, агент поможет по шагам. Рабочий доступ нельзя отключать до проверки нового.

### Если произошла авария

Запускайте промпт с доверенного компьютера. Опишите, что произошло, когда это заметили и что уже сделали. **Если утечка или уничтожение данных продолжаются, сообщите об этом первым.**

До выяснения причины не очищайте журналы событий (логи), не удаляйте подозрительные файлы и не восстанавливайте резервную копию поверх работающей базы. Новые секреты не вводите на подозрительном сервере; необработанные логи и материалы расследования не публикуйте в чате или Git.

Обычный сбой не означает взлом. Например, истёкший сертификат сам по себе не требует нового сервера или замены всех ключей. Агент выбирает действия по фактам и при необходимости объясняет, почему нужен специалист.

## 3. Что агент делает сам, а что остаётся вам

Агент выбирает технические решения, исправляет подтверждённые проблемы, добавляет нужные проверки и проверяет свою работу. Уже работающую защиту он использует повторно; объём настройки зависит от проекта.

Ваше решение нужно, если возможны ещё не согласованные потеря данных, недоступность сайта или потеря доступа, расходы, необратимые действия либо существенное расширение задачи и полномочий. Агент должен объяснить последствия и рекомендовать вариант. Разрешать каждую команду и повторно подтверждать неизменившееся решение не нужно.

**Вы самостоятельно** сохраняете изменения (commit), отправляете их в GitHub (push), принимаете их в основную версию (merge), включаете настройки GitHub и добавляете секреты. Агент готовит файлы и даёт конкретные шаги. Также может понадобиться действие в кабинете хостинга или проверка получения уведомления.

Если старое ограничение доступа мешает следующему этапу, попросите агента назвать необходимое узкое изменение и способ вернуть ограничение. Не отключайте всю защиту. Локальный режим «только чтение» сам по себе не ограничивает права подключения к серверу.

## 4. Проверьте итог и включите подготовленное

В конце агент должен понятно показать: **что исправлено, что проверено, что осталось и что делать дальше**. Техническую проверку проводит агент; ваше чтение отчёта её не заменяет.

Обращайте внимание на состояние каждого механизма:

| Статус | Что это значит |
| --- | --- |
| Подготовлено локально | Файлы готовы, но автоматическая проверка или выпуск могут ещё не работать |
| Включено пользователем | Вы опубликовали изменения и включили настройки; результат запуска ещё нужно проверить |
| Проверено в работе | Есть подтверждённый результат запуска или доставки уведомления |
| Не проверено / ошибка | Агент указал пробел и следующий шаг; считать механизм работающим пока нельзя |

Выполните оставшиеся шаги из инструкции агента и передайте ему результаты запусков либо дайте прочитать их через доступные инструменты. Он проверит работу настроек и фактическую нагрузку автоматических проверок. Секреты для этого в чат не присылайте.

Выберите уведомления: **Telegram + email + GitHub**, **email + GitHub** или **только GitHub**. Проверить нужно доставку по выбранным каналам; Telegram необязателен.

Цель первых двух промптов — автоматические проверки кода и работы сайта, публикация новых версий, безопасный возврат к предыдущей версии и уведомления. После настройки обычные обновления проходят через проверенную автоматизацию. Ваше подтверждение выпуска может оставаться частью выбранного порядка; запускать второй промпт перед каждым обновлением не нужно.

Исправление в GitHub ещё не означает, что исправленная версия уже работает на сайте. Агент должен проверять это отдельно. Непроверенный возврат к старой версии нельзя объявлять работающим.

## Если нужно продолжить в другом чате

Прерванную работу можно продолжать в прежнем чате. Для нового откройте тот же проект с актуальными файлами и результатами предыдущей работы, вставьте соответствующий промпт целиком и добавьте:

> Продолжи работу по `docs/safe/PROGRESS.md`. Сначала сверь журнал и карту документов с фактическим состоянием проекта и сервера, если он участвует в задаче.

Этот файл — журнал работы, который ведёт агент. Через него и документы проекта передаётся контекст; рассчитывать на автоматическую передачу переписки не нужно. Если используете другую папку, ветку или копию проекта, проверьте, что результаты доступны и там.

Если журнала ещё нет, передайте краткий итог предыдущего чата без секретов и укажите доступные документы. Уже выполненные переносы и преобразования данных, замену ключей и переключения сайта агент должен проверить, прежде чем повторять.

Для большого объёма работы агент может привлекать субагентов — дополнительных AI-помощников. Настраивать их специально не требуется; они расходуют дополнительные лимиты, а за итоговую проверку отвечает основной агент.

Промпты помогают проверить и улучшить защиту в определённых границах. Их выполнение не гарантирует отсутствие всех уязвимостей: непроверенные области и оставшиеся риски должны быть указаны в результате.
